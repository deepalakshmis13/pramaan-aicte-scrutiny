## Backend — `backend/tests`
- **`test_workflow.py`** — institution creates an application, empty submission refused with the missing list, uploads every
  checklist document, replaces one, submits → appears in the officer queue (drafts never do) → Verify Application runs the
  engine (expired NOC detected, scanned receipt read by OCR) → reject needs a 15-character reason; accepting a flagged document
  needs a note → cannot move to decision while a document is rejected → notice candidates → past deadline refused → notice sent
  in one step and confirmed (status *issued*, correct institution, delivered) → second notice blocked while one is open →
  **notice visible on the institution’s Notices, Overview and notifications, and 404 for another institution** → institution
  sees the rejection reason but no internal data → responds with a corrected NOC → resubmission v2 → re-verified replacement
  shows checks passed → officer accepts → findings and notice items resolved → decision history kept across versions → move
  to decision → another officer records the decision → institution sees it; passport shows both submissions.
  Also: manual verification with field confirmation, internal report hidden from institutions, dashboard score equals the sum
  of its listed factors, CSV export.
- **`test_security.py`** — login, session probe, CSRF header, role separation, institution isolation, drafts private to the
  institution, internal fields hidden, invalid IDs, upload validation (wrong type, empty, corrupt, off-checklist, officer
  upload refused), storage path traversal, audit-chain tamper detection.
- **`test_verification.py`** — Crossref match / mismatch / no record / unreachable / simulated, Scopus without credentials,
  native and OCR extraction, seeded scenarios, rule versioning.

## End-to-end — `frontend/e2e`
- **`journey.spec.ts`** — the complete workflow in the browser: institution creates an application → sees the checklist →
  early submit lists what is missing → uploads 14 files → submits → officer finds it, clicks **Verify Application**, opens a
  document (page image, OCR text) → rejects the expired NOC with a reason, accepts the rest → **Create Deficiency Notice →
  Send Notice** → a different institution does **not** see it → Northfield sees it on Overview and Notices → responds with a
  corrected NOC → officer accepts the new version → **Move to decision** → second officer records the decision → institution
  sees the decision. Fails on any browser console error.
  Plus: invalid IDs / unauthorised URLs / refresh; external verification shown as unavailable; server error state.
- **`routes.spec.ts`** — every route for each role renders without errors or dead links; no horizontal overflow at phone width.

Fixtures for the journey are generated by `python -m seed.e2e_fixtures` (run from `backend/`). Playwright reseeds
`aicte_verify_test` and serves on port 8001, so demo data in `aicte_verify` is untouched.
